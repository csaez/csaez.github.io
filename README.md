# csaez.github.io

Source of [cesarsaez.com](https://www.cesarsaez.com), the personal resume site
of Cesar Saez. A small Python script renders Markdown content through Jinja2
templates into static HTML, hosted on GitHub Pages. There is no JavaScript
framework and no CSS build step.

The same content produces three outputs:

- a single-page site (`index.html`) with light and dark Tokyo Night themes
- a print layout (two A4 pages, ATS-friendly) used to export the PDF resume
- `llms.txt`, a plain Markdown copy of the resume for LLM crawlers

## Quick start

Requires Python 3.11+.

```
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python build.py
python -m http.server -d dist
```

Then open http://localhost:8000. Rebuild after every change; `dist/` is
generated and git-ignored.

## Project layout

```
config.toml        site metadata, contact, social links, section order
content/*.md       all the resume text
templates/         index.html (Jinja2) and icons/icon-<name>.html (SVG)
static/            copied as-is: style.css, fonts/, images/avatar.jpg, favicon.png
build.py           the generator; writes everything to dist/
.github/workflows/pages.yml   build and deploy on push to main
```

## Editing the content

Content lives in `content/`. Which files are shown, and in what order, is set
by `sections` in `config.toml`.

| File | Format |
| --- | --- |
| `intro.md` | One plain Markdown paragraph |
| `impact.md`, `skills.md` | One bullet per item |
| `experience.md`, `education.md`, `recommendations.md` | One `##` per entry (company, school or person), then `###` lines for details (position, dates), then the Markdown body |

Example entry:

```
## Company, City

### Job title

### Jan 2020 - Present

- **Headline achievement.** Supporting detail.
```

Notes:

- Consecutive `experience.md` entries with the same `##` title are grouped
  under one company heading.
- `recommendations` is not in `sections` by default, so it is not rendered.
  Add it to the list to show it on screen; it is always hidden in print.
- Typographic quotes and dashes are generated by Markdown (`smarty`), so write
  plain ASCII.

## Configuration (`config.toml`)

- `title`, `description`, `url` - page metadata
- `name`, `headline`, `email` - header text
- `contact` - items in the header line. Use `{ text = "...", print_only = true }`
  to keep one off the screen (e.g. phone number)
- `show_avatar`, `looking_for_work` - toggles
- `sections` - order and visibility; remove a name to hide it
- `[[links]]` - `label`, `url`, `icon`, plus optional `in_header` (also print
  the URL in the contact line), `print_only` (no icon on screen) and `rel`

To support a new `icon` value, add `templates/icons/icon-<name>.html`.

## Styling and print

- `static/style.css` is plain, hand-written CSS. Rules for unused elements
  were pruned, so check it when adding new markup.
- Print targets two A4 pages and ATS-friendly text extraction: one column, no
  letter-spacing on headings, and fonts self-hosted in `static/fonts/` so the
  PDF embeds TrueType fonts. If you add a font weight or style used in print,
  add its `@font-face` too, or Chrome synthesizes a Type 3 font. Check with
  `pdffonts` and `pdftotext` after printing.

## Publishing

Pushing to `main` runs `.github/workflows/pages.yml`, which installs
`requirements.txt`, runs `build.py` and deploys `dist/` to GitHub Pages. In the
repository settings, Pages > Source must be set to "GitHub Actions".
